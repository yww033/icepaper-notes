0一分鐘版本

先把整篇濃縮成三句話。之後讀到任何細節，都可以問自己：「這是在講三句話中的哪一句？」

問題用電腦從過去的資料學規則、預測未來時，常常會「練習時很準，真的上場卻不準」。原因之一是過去和未來的資料長得不一樣；另一個原因是給電腦的線索不夠多。
做法先用程式自動產生大量新線索（解決線索不夠），再用一個統計檢查把「過去和未來長得不一樣」的線索丟掉（解決資料不一樣）。
結果在洗錢帳戶和配對交易兩個案例上有效；在保險案例上一開始無效，作者發現是因為2020 年的保險新法規改變了民眾的購買行為。避開法規期間之後，方法就有效了。

1先修觀念：讀這篇之前要懂的 11 件事

依照「先懂這個，下一個才看得懂」的順序排列。每個觀念都有三層：一句白話、一個生活比喻、它在這篇論文裡扮演什麼角色。

A · 機器學習在做什麼

① 機器學習 Machine Learning

給電腦看大量「過去的例子和答案」，讓它自己找出規律，再拿去猜新的例子。

補習班老師看過幾千個學生的成績和錄取結果，慢慢抓到「模擬考幾分、哪科強的人通常會上」，再拿這個經驗去猜今年的學生。

要猜的是：一張保單會不會成交、一個銀行帳戶是不是洗錢帳戶、一組股票該怎麼交易。主要用的「學生」是一種叫 XGBoost 的模型，你可以先把它當成一個很會做選擇題的學生。

② 特徵 Feature

電腦用來猜答案的「線索」。

醫生判斷你是不是感冒，看的是體溫、咳嗽、喉嚨痛——這些就是特徵。

保險案例的特徵像是：被保人年齡、保費、保額、買的是哪種保險、客戶忠誠度、業務員的年資和性別。整篇論文其實都在討論「線索要怎麼準備、哪些線索該留、哪些該丟」，這件事叫做特徵工程。

③ 訓練集與測試集 Training set / Test set

把資料分兩份：一份給電腦練習（訓練集），另一份藏起來，最後才拿來考它（測試集）。

訓練集是平常寫的練習題，測試集是期末考。如果期末考題目事先被看過，分數就不能代表真實程度。

作者依時間切：2018/9～2020/4 當練習題，2020/5～2020/9 當期末考。用「過去」預測「未來」，這個做法是正確的。

④ 過擬合與欠擬合 Overfitting / Underfitting

過擬合＝把練習題背得滾瓜爛熟，但換題目就不會；欠擬合＝連練習題都沒學好，因為資訊太少或方法太簡單。

過擬合像死背考古題的學生；欠擬合像只讀了課本第一章就上考場的學生。

作者診斷他的模型兩種問題都有，所以開了兩帖藥：用 DFS 增加線索治「欠擬合」，用 KS 檢定丟掉壞線索治他認為的「過擬合」。

B · 怎麼評分

⑤ F1 分數 F1 Score

0 到 1 之間的分數，專門衡量「少數但重要的那一類，有沒有被抓到、抓得準不準」。越接近 1 越好。

100 張保單只有 15 張成交。如果電腦偷懶全部猜「不會成交」，正確率還有 85%——看起來很高，其實一張成交的都沒抓到。F1 就是為了揪出這種偷懶而設計的分數。

整篇論文都用 F1 比較好壞。保險案例的 F1 大約在 0.3～0.4，所以看到「從 0.381 進步到 0.409」這種數字，要知道這是在很低的起點上小幅進步。

📊 看圖：為什麼不能只看正確率

⑥ 資料不平衡 Imbalanced data

某一類的資料特別少，電腦就容易忽略它。解法是把少數類的「份量」調高。

班上 85 個人說要吃麥當勞、15 個人說要吃壽司。如果每人一票，壽司永遠選不上；所以讓壽司組每人算 5.4 票。

成交保單 79,159 張、未成交 427,462 張，比例大約 1：5.4。作者試了兩種方法：把成交保單複製到一樣多（過採樣），或讓每張成交保單算 5.4 倍重（加權）。兩種都讓 F1 從 0.21 跳到 0.37～0.39，這是全文效果最明顯的一步。

C · 這篇的主角：資料集偏移

⑦ 分佈 Distribution

一群數字「長什麼樣子」：大部分集中在哪裡、分散得多開。

把全班身高畫成長條圖，A 班集中在 160～170 公分，B 班集中在 170～180 公分，這兩班的身高「分佈」就不一樣。

作者關心的是：同一條線索（例如保費），在練習期和考試期的分佈是不是一樣。

⑧ 資料集偏移 Dataset shift

練習時的資料和上場時的資料長得不一樣，學到的規則就不管用了。

整學期都練選擇題，期末考卻全部是申論題。你不是不認真，而是題型變了。

保險案例的期末考期間（2020/5～9），剛好碰上金管會 2020 年 7 月的新規定：儲蓄險的條件變差、很多商品要停賣。所以 5 月大家搶著買、7 月之後幾乎沒人買。練習期學到的「什麼樣的保單會成交」，到了考試期就不準了。

⑨ KS 檢定與 p 值 Kolmogorov-Smirnov test / p-value

KS 檢定用來比較兩堆資料的分佈像不像；p 值告訴你「這個差異會不會只是巧合」。p 值越小，越不像巧合，也就是兩邊真的不一樣。

把 A 班和 B 班的身高長條圖疊在一起，看兩條曲線最遠差多少。差很多、而且不太可能是運氣造成的，p 值就會很小。

作者對每一條線索都做 KS 檢定，p 值接近 0 的就丟掉，因為代表它在練習期和考試期長得不一樣，留著反而會誤導電腦。這是全文最核心的想法。

⑩ 判別式學習 Discriminative learning（又叫對抗驗證）

另外請一個電腦「偵探」，猜每一筆資料是來自練習期還是考試期。猜得越準，代表兩期差越多。

把兩班學生混在一起，請人只看身高猜他是哪一班。如果一猜就中，代表兩班身高差很多；如果怎麼猜都像丟銅板，代表兩班差不多。

偵探的分數也用 F1：1.0 代表完全分得出來（偏移很嚴重），越低代表兩期越像。作者用它來驗證「丟掉線索之後，兩期是不是變得比較像了」。

D · 自動產生線索

⑪ DFS 深度特徵合成 Deep Feature Synthesis

當資料分散在好幾張相關的表格時，程式自動把表格串起來，用加總、平均、最新一筆等方式，算出大量新的線索。

你有「訂單表」「客戶表」「業務員表」。程式會自動算出「這位客戶總共買了多少」「這位業務員平均每張單多少錢」「這位客戶最近一次改保單是哪一年」——這些都是人工可能想不到的新線索。

保險案例用客戶、業務員、保單三張表，自動產生了 1,242 個新線索。這是作者用來治「欠擬合」的藥。

E · 財金背景（三個案例）

保單成交、警示帳戶、配對交易

保單成交：業務員提出一份保險建議書，客戶最後有沒有買。
警示帳戶：被警方列為疑似詐騙或洗錢用途的銀行帳戶，數量非常少。
配對交易：找兩支平常走勢綁在一起的股票，當兩者價差突然拉開，就買便宜的、賣貴的，等價差回到正常時獲利。

配對交易就像兩個總是並肩走路的朋友：其中一個突然走快了，你就賭他等一下會放慢腳步、回到朋友身邊。

2論文的故事：保險案例的五幕劇

74 頁裡大部分篇幅都在講保險案例。把它想成一齣五幕劇，每一幕只記一個重點和一個數字就夠了（F1 越高越好，最高是 1）。

先做出能用的模型

成交保單太少，電腦一開始幾乎都猜「不會成交」。作者把成交保單的份量調高後，分數大幅改善。

沒處理 0.21複製成交保單 0.37加權 5.4 倍 0.39

→ 全文效果最明顯、也最沒有爭議的一步。

人工加線索，只有一點點進步

作者加入業務員的年資、性別，以及「年資以外的工作經驗」，也試了各種把客戶等級變成數字的方法，還試著把商品資訊壓縮。

加業務員資訊 0.368 → 0.386各種編碼方式 差不到 0.006壓縮商品資訊 反而降到 0.31

→ 人工想線索效果有限，這替後面「自動產生線索」鋪路。

發現：練習題和期末考長得不一樣

KS 檢定顯示，幾乎每一群客戶的年齡、保費、保額，在練習期和考試期的分佈都不一樣；偵探也能大致分出兩期的資料。

KS 的 p 值 幾乎全部 ≈ 0偵探分辨的 F1 0.69

→ 證實有「資料集偏移」。

照計畫丟掉壞線索，結果反而變差

作者用 KS 丟掉分佈不一樣的線索，預測卻變差了。他去查原因，發現 2020 年 5 月有搶買儲蓄險的熱潮、7 月新規上路後購買量跌到新低——考試期本身就因為法規而變了樣。

丟掉線索後 0.378 → 0.344

→ 這是全文的轉折點：方法不是萬靈丹，遇到法規這種「突然的改變」會失效。

先補線索，再避開法規期：終於有效

作者先用 DFS 自動產生 1,242 個新線索，分數提高了。接著把資料限制在法規出現之前（2018/9～2020/4），重新切練習與考試期，再用 KS 丟掉壞線索——這次預測變好，偵探也比較分不出兩期了。

只用原本線索 0.351加 DFS 0.393加 DFS 再用 KS 0.418偵探 F1 1.0 → 0.535

→ 全文最重要的證據：在「沒有突然改變」的期間，先補線索、再丟壞線索，是有用的。

📊 看圖：五幕劇的分數變化

另外還有一個小支線：作者測試了一種會「自動調整樣本份量」的進階方法（Khan 等人提出），結果不如最簡單的 5.4 倍加權，所以作者主張「照數量比例加權」就夠了。

3三個案例的結果，一張圖看完

作者用三個不同的財金問題測試同一套方法，想證明它不是只在某一份資料上剛好有效。

保險：保單會不會成交台灣某保險公司 2018～2020 年、約 50 萬張保單。
一開始無效 → 避開法規期後有效
洗錢：帳戶是不是警示帳戶台灣某銀行 2018 年 4～9 月的交易紀錄。KS 剛好抓出兩個會誤導電腦的線索。
有效，F1 最高約 0.80
配對交易：該怎麼買賣台灣 50 成分股 2013～2016 年的高頻資料，比較三種線索：價差、股價、報酬。
「價差」最穩定，報酬大多最高

4讀的時候要打個問號的地方

懂了故事之後，下一步是「不要全信」。以下三點是這篇最值得注意的問題，也是跟教授討論時最好的切入點。

① 期末考的題目，其實被偷看過作者在每次訓練時，都挑「期末考分數最高的那一次」來報告。這就像考完試再回頭改答案，所以很多分數可能比真實能力高一點。
② 有一個實驗直接用了期末考的資料為了證明 KS 有效，作者有一組實驗直接比較「練習期 vs. 考試期」來丟線索，得到 0.427。但真實情況下，我們事先不可能拿到未來的資料，所以這個數字不能當作方法有效的證據。
③ 「顯著進步」常常只差一點點例如加入業務員資訊只從 0.368 進步到 0.386，而且每個實驗都只做一次，沒有檢查這樣的差距會不會只是運氣。

6記住它：5 個自我檢查題

先自己在腦中回答，再點開對照。答不出來的題目，回頭看對應的那一節。

Q1　這篇想解決的兩個問題是什麼？
(1) 過去和未來的資料長得不一樣（資料集偏移）；(2) 給電腦的線索不夠多（欠擬合）。→ 第 0 節
Q2　KS 檢定在這篇裡用來做什麼？p 值小代表什麼？
用來比較每條線索在練習期和考試期的分佈像不像；p 值越小，代表兩期越不一樣，作者就把這條線索丟掉。→ 觀念 ⑨
Q3　保險案例一開始為什麼失敗？
考試期剛好碰上 2020 年 7 月的保險新法規，5 月搶買、7 月之後幾乎不買，資料突然改變，用練習期判斷要丟哪些線索就不準了。→ 第 2 節第四幕
Q4　全文最重要的一組數字是什麼？
避開法規期之後：預測 F1 從 0.351 → 0.393（加 DFS）→ 0.418（再加 KS），偵探 F1 從 1.0 降到 0.535。→ 第 2 節第五幕
Q5　這篇最值得懷疑的地方是什麼？
挑「期末考分數最高的那一次」來報告，以及有一組實驗直接用了期末考的資料，所以部分分數可能偏高。→ 第 4 節
